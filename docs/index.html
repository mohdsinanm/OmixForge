System Requirements & Prerequisites

OmixForge orchestrates advanced bioinformatic computations offline. Ensure your machine meets the minimum resources required for workflow containerization.

Hardware Specifications

  • Operating System: Linux (Ubuntu 20.04+ or Debian 11+ recommended).
  • System Memory (RAM): Minimum 8GB (16GB+ recommended for running multiple heavy pipelines).
  • Disk Space: Adequate space for raw FASTQ inputs, Docker container layers, and nextflow outputs.

Core System Dependencies

Before launching OmixForge, the system requires the following runtime dependencies:

  1. Docker Engine: Used for containerized execution of pipeline steps to preserve software environments.
  2. Nextflow Engine: The pipeline runner engine. Requires Nextflow in the system $PATH.
  3. Java Runtime Environment (JRE): Nextflow requires OpenJDK 11 or later.

Installing Nextflow and Docker on Debian/Ubuntu

Follow these standard steps to configure your system for local pipeline runs.

Part A: Installing Docker Engine

# 1. Update Package Index
sudo apt update

# 2. Install Required Dependencies
sudo apt install -y ca-certificates curl gnupg lsb-release

# 3. Add Docker's Official GPG Key
sudo install -m 0755 -d /etc/apt/keyrings
curl -fsSL https://download.docker.com/linux/ubuntu/gpg | sudo gpg --dearmor -o /etc/apt/keyrings/docker.gpg
sudo chmod a+r /etc/apt/keyrings/docker.gpg

# 4. Set Up the Docker Repository
echo "deb [arch=$(dpkg --print-architecture) signed-by=/etc/apt/keyrings/docker.gpg] https://download.docker.com/linux/ubuntu $(lsb_release -cs) stable" | sudo tee /etc/apt/sources.list.d/docker.list > /dev/null

# 5. Install Docker Engine
sudo apt update
sudo apt install -y docker-ce docker-ce-cli containerd.io docker-buildx-plugin docker-compose-plugin

Note for Debian users: Replace the repository URL in Step 4 with https://download.docker.com/linux/debian.

Part B: User Permissions (Recommended)

To let OmixForge invoke Docker containers without requiring administrator privileges (sudo), run:

sudo usermod -aG docker $USER
newgrp docker

Part C: Installing Nextflow

Nextflow requires Java 11+. Use the following configuration steps:

# 1. Install Java
sudo apt update
sudo apt install -y openjdk-11-jre-headless

# 2. Download and install Nextflow
curl -s https://get.nextflow.io | bash

# 3. Make Nextflow globally available
sudo mv nextflow /usr/local/bin/

First Launch & Access Modes

On launching OmixForge, you are greeted with the profile configuration screen. You can select between two access modes:

1. Public Mode

The standard operation mode for standard environments. Requires no setup passwords or access keys. Highly recommended for personal workstations and general workflows.

2. Private Mode

Designed for shared server environments, sensitive data hubs, or clinical computing layouts. On first launch, you are asked to register a username and passphrase.

Important: Passwords cannot be recovered under Private Mode. All run parameters, log headers, and output file assets are encrypted using Fernet (AES-128) logic. Losing your credentials results in permanent loss of output access.

Interface Layout

  • Sidebar: Collapsible navigation to hop between Dashboard, Sample Prep, Downloader, Pipeline Status, and Plugin Store.
  • Main Frame: Displays the controls, charts, and tables for the active panel.
  • Quick Controls: Bottom status indicators and header menus.

Pipeline Dashboard

The dashboard acts as your main bioinformatics cockpit to manage local pipelines and fetch new configurations.

Importing Pipelines

  1. Navigate to the Import tab.
  2. Click Refresh Pipelines to query index schemas directly from the global nf-core database.
  3. Select your desired pipeline (e.g., rnaseq, sarek, ampliseq) from the dropdown list.
  4. Verify description details, release headers, and click Import Pipelines to pull config assets locally.

Managing Local Workflows

  • Click the Pipelines tab to inspect downloaded environments.
  • Select a local workflow card to review installation paths, metadata, and deletion buttons.

Sample Preparation & Sheets

Bioinformatics pipelines require metadata sheets linking sample tags to sequence files. OmixForge includes an interactive grid editor.

Grid Features

  • Interactive Spreadsheet: Double-click cells to modify paths, names, and strand metrics.
  • Row/Column Management: Add or remove columns/rows on the fly using header click modifiers.
  • Header Customization: Click column headers to adjust structural labels matching nextflow expectancies.

Auto-Discovery (Magic Loader)

Instead of typing folder pathways manually, use the automated scanner:

  1. Click Load files from Dir.
  2. Browse and select a folder containing sequence outputs (e.g., FASTQ, FASTA, or BAM).
  3. OmixForge recursively parses files. It intelligently identifies pairing suffixes (e.g. _R1/_R2, _1/_2) and populates the CSV rows accordingly.

ENA Fastq Downloader

A built-in utility to download run read files from the European Nucleotide Archive (ENA) API directly.

Accession Types Supported

  • SRR: NCBI Sequence Read Archive runs.
  • ERR: ENA Run accessions.
  • DRR: DDBJ Run accessions.

How to Retrieve Records

  1. Go to Samples → ENA Fastq Downloader tab.
  2. Paste space-separated accession identifiers (e.g., SRR10376955 SRR10376956) or upload a .txt file lists containing one accession per line.
  3. Click Fetch Accessions to query ENA metadata.
  4. Review success/failure records in the results tables.
  5. Select download path and click Download All Files to pull fastq files in background worker pools.

Running Workflows

Executing bioinformatics steps is rendered simple through visual schema translation.

Dynamic Configuration Generation

When selecting Run on a local pipeline, OmixForge parses its nextflow_schema.json file to render form fields dynamically. You configure settings (e.g., trimmers, genome assembly version) using toggles and dropdown inputs rather than text files.

Executing Pipelines

  1. Input Sheet: Click browse to target the CSV metadata sheet created in Sample Prep.
  2. Output Folder: Select target directory to write processed datasets.
  3. Profile Choice: Choose runtime environment profiles:
    • docker: Uses local docker engine (default).
    • singularity: For shared high-performance computing centers (HPC).
    • test: Runs standard mock files.
  4. Click Launch. Active execution status locks duplicate pipeline starts.

Private Mode & Output Encryption

In data-sensitive environments, pipeline assets must be protected against local snooping.

Fernet AES-128 Encryption

If Private profile is enabled, OmixForge automatically encrypts nextflow result streams and generated CSV matrices into .enc formats. These files are unreadable by standard file explorers.

Decrypting Assets

To decrypt outputs for downstream presentation:

  1. Open the Results panel.
  2. Locate and select the target encrypted file (.enc).
  3. Click the Decrypt button. Input your session password. Decrypted results write to target paths.

Plugins & Extensibility

OmixForge features a modular codebase allowing developers to add plugins for extra visual analytics or calculations.

Finding and Installing Plugins

  1. Open the Plugin Store tab in the sidebar.
  2. Browse the community collection of visualization templates or analysis wrappers.
  3. Click Install. Once fetched, plugin routes show inside the sidebar.

Uninstalling Plugins

Go to the Manage section inside the Plugin Store, select the active extension, and press Remove to delete code assets clean.

Review the OmixForge Plugins repository for developer templates and guides.

Troubleshooting Common Issues

1. "Docker not found" or permission failures

  • Ensure the docker daemon is active: sudo systemctl start docker
  • Confirm user permissions: groups must list docker. Log out and log back in to activate groups.

2. Pipelines fail instantly

  • Check status logs: Common error includes missing input files or directory discrepancies. Verify that the absolute file paths inside your sample CSV exist on disk.

3. Application interface freeze or unresponsive widgets

  • Bioinformatics pipelines are heavily memory-bound. If your workstation runs out of RAM, the user interface thread may lag. Restrict CPUs and memory limits inside nextflow configs or the settings panel.
